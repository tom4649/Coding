# NumPy / PyTorch のmmap

---

## 1. 仮想記憶（Virtual Memory）

現代のOSにおいて、プログラムが直接アクセスするメモリは物理メモリ（RAM）そのものではなく、OSが用意した仮想的なメモリ空間（仮想アドレス空間）である。

OSは仮想アドレスと物理アドレスの対応表（ページテーブル）を管理しており、プログラムから要求があった際に、必要な分だけ物理メモリを割り当てる。この仕組みにより、物理メモリの容量を超えるプログラムを実行したり、複数のプロセス間でメモリ領域を安全に隔離したりすることが可能になる。

---

## 2. メモリマッピング（mmap）の仕組み

メモリマッピング（`mmap`）は、この仮想記憶の仕組みを応用し、**「ディスク上のファイル」を「仮想メモリ空間」に直接マッピング（対応付け）する技術**である。

通常、ファイルを開いてデータを読み込む場合、OSはディスクから物理メモリ（RAM）へデータを丸ごとコピーする。しかし、`mmap` を使用すると、OSは以下のような「遅延ロード」を行う。

1. **仮想アドレスの確保**：ファイルサイズ分の架空の住所（仮想アドレス）だけを確保する。この時点では物理メモリは消費しない。
2. **ページフォールトの発生**：プログラムが特定のデータ（例：配列の要素）にアクセスした瞬間、まだ物理メモリがないためCPUが「ページフォールト」という中断信号を出す。
3. **オンデマンド読み込み**：信号を受けたOSが、ディスクから必要な部分（通常は4KB単位のページ）だけを物理メモリに読み込み、処理を再開する。

この一連の動作により、巨大なファイルであってもロード時間がほぼ「ゼロ」になり、物理メモリの消費を必要最小限に抑えることができる。



---

## 3. NumPy と PyTorch における高速ロードの引数

NumPy と PyTorch は、このOSレベルの `mmap` をPythonから簡単に利用するための引数を提供している。

### NumPy: `mmap_mode`
`np.load()` の `mmap_mode` 引数に、読み込み専用の `'r'` などを指定することでメモリマップが有効になる。巨大な `npy` ファイルを扱う際の必須テクニックである。

```python
import numpy as np

# 通常のロード：ファイル全体を物理メモリにコピーする（大容量ファイルではOOMの危険あり）
# data = np.load("huge_data.npy")

# mmapを使用したロード：一瞬で完了し、アクセスした部分だけがロードされる
data_mmap = np.load("huge_data.npy", mmap_mode="r")

# 必要になった一部の領域だけが、裏側でOSによって物理メモリに配置される
print(data_mmap[100:200])

```

### PyTorch: `mmap`

```python
import torch

# mmapを使用してモデルの重みを読み込む（CPUメモリをほぼ消費しない）
weights_mmap = torch.load("large_model.pt", mmap=True)

# 必要な重みデータだけを、CPUメモリを素通りさせるように直接GPU（VRAM）へ転送する
# model.load_state_dict(weights_mmap)
```

現在のLLM（大規模言語モデル）のサービングエコシステム（Hugging Faceの safetensors や vLLM など）では、この mmap の特性を最大限に活かせるバイナリ構造が採用されており、モデルのロード時間短縮と省メモリ化においてコア技術として機能している。
