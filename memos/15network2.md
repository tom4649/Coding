# ネットワークインフラ: レイヤー2からレイヤー3

## 1. ネットワーク機器の基本用語：ブリッジとルータの違い

ネットワークをセグメント（分割）し、データを正しい目的地へ届けるための代表的なハードウェアの役割を整理する。

* **ブリッジ（Bridge） / L2スイッチ**
    * **動作レイヤー:** **「第2層：データリンク層」**
    * **仕組み:** ネットワークを流れるパケットの**MACアドレス**を読み取り、どのポートにその端末がいるかを学習する（MACアドレステーブル）。同じセグメント内の端末同士の通信を中継し、不要なポートにはデータを流さない（コリジョンドメインの分割）役割を果たす。
* **ルータ（Router） / L3スイッチ**
    * **動作レイヤー:** **「第3層：ネットワーク層」**
    * **仕組み:** **IPアドレス**を読み取り、異なるネットワーク（セグメント）同士を接続して、パケットを目的地までどの経路で届けるべきかを判断する（ルーティング）。

---

## 2. レイヤー2の冗長化と高速化：STP と リンクアグリゲーション

ネットワークの断線（障害）に備えて回線を二重化・ループ化する際、L2レイヤーでの制御が必須となる。

### スパニングツリープロトコル（STP: Spanning Tree Protocol）
* **解決する問題:** L2スイッチ同士を冗長化のためにループ状（輪っか状）に接続すると、ネットワーク内でフレームが永遠にぐるぐると回り続ける**「ブロードキャストストーム」**が発生し、ネットワーク全体が完全にダウンする。
* **仕組み:** スイッチ間で「BPDU」という制御情報を交換し合い、ネットワーク全体のトポロジー（構造）を把握する。その中から1台の「ルートブリッジ（頂点）」を決め、ループを解消するために**あえて特定のポートを論理的に遮断（ブロック）**し、一本道の木構造（ツリー）を作り出す。
* **障害時の挙動:** メインの経路が断線すると、ブロックされていたポートが自動的に開放され、通信が数秒〜数十秒でバックアップ経路へ切り替わる。

### リンクアグリゲーション（Link Aggregation / LAG）
* **仕組み:** STPが「予備の回線を眠らせておく」のに対し、リンクアグリゲーションは**複数本の物理的なLANケーブルを論理的に「1本の太い回線」として束ねる**技術である。一般的にLACP（Link Aggregation Control Protocol）というプロトコルが使われる。
* **メリット:** * **帯域幅の拡大:** 1Gbpsの回線を4本束ねれば、論理的に4Gbpsの通信が可能になる。
  * **耐障害性（フォールトトレランス）:** 1本のケーブルが断線しても、残りの3本で通信を継続できるため、通信が途切れない。

## 3. インターネット接続の冗長化：マルチホーミング

* **仕組み:** 企業のネットワークやデータセンターにおいて、**複数の異なるインターネットサービスプロバイダ（ISP）と同時に回線を契約・接続する**構成である。
* **目的:** 単一のプロバイダ（シングルホーム）だけを利用していると、そのプロバイダで大規模な通信障害が起きた際に自社サービスが完全に停止する。マルチホーミングにしておけば、ISP Aがダウンしても自動的にISP B経由でインターネットへの通信を維持できるため、可用性が劇的に向上する。

---

## 4. ネットワーク層のパラダイムシフト：IPv4 と IPv6

インターネットの基盤であるIPアドレスの規格であり、現在も移行が進められている。

* **IPv4（Internet Protocol version 4）**
    * **アドレス長:** 32ビット（約43億個）。
    * **限界:** インターネットの爆発的な普及（IoT機器やスマホの増加）により、アドレスが完全に枯渇している。そのため、実務ではプライベートIPとグローバルIPを変換する「NAT/NAPT」の技術が必須となっている。
* **IPv6（Internet Protocol version 6）**
    * **アドレス長:** 128ビット（事実上、無限に近い個数）。
    * **特徴:** 全ての機器に直接固有のグローバルIP（IPアドレス）を割り当てられるため、NATが不要になりエンドツーエンドの通信がシンプルになる。また、パケットのヘッダー構造が簡素化され、ルータでの処理効率が向上している。

## 5. 無線とアクセスの古典的プロトコル：SSID、CSMA/CD、ATM

### SSID（Service Set Identifier）
* **概要:** 無線LAN（Wi-Fi）における**「アクセスポイントの識別名（ネットワーク名）」**である。混在する電波の中から、自分が接続すべき正しい無線ネットワークを識別するために使用される。

### CSMA/CD（Carrier Sense Multiple Access with Collision Detection）
* **概要:** 有線LAN（イーサネット）の初期に利用されていた、**1本の同軸ケーブルを全員で共有して通信するための衝突回避プロトコル**である。
* **プロセス:** 1. **Carrier Sense:** 回線が空いているかを確認し、空いていればデータを送信する。
  2. **Multiple Access:** 複数の端末が同時に送信を試みることがある。
  3. **Collision Detection:** データが衝突（コリジョン）したことを検知したら、送信を即座に中止し、各端末が「ランダムな時間」だけ待ってから再送する。
  *(※現代のスイッチングハブを使用したフルデュプレックス（全二重）通信では、送信と受信の経路が分かれているため衝突自体が発生せず、CSMA/CDは実質的に使われていない。)*

## 6. パケット交換方式 と ATM交換方式 の違い

ネットワークでデータを送受信する際、「大きなデータを細切れにして送る」という大枠の思想は共通しているが、その「細切れの仕方のルール」によって、一般的なパケット交換方式とATM交換方式に分かれる。

---

### 1. パケット交換方式（Packet Switching）
現在、私たちが使っているインターネット（IPやイーサネット）の基盤となっている通信方式である。

* **仕組み:** データを**「パケット（ packet：小包）」**と呼ばれる塊に分割し、それぞれに宛先情報（ヘッダー）を付与してネットワークに流す。
* **最大の特徴（可変長）：**
  パケットのサイズは一律ではなく、データの種類やネットワークの規格に応じて**サイズが柔軟に変わる（可変長）**。例えば、短いテキストなら小さなパケット、高画質な画像なら大きなパケット（一般的な最大サイズは1,500バイト程度）として一度に送る。
* **メリット:** データの大きさに合わせてパケットを作れるため、無駄な隙間（余白）が生まれず、回線の利用効率が非常に高い。
* **デメリット:** パケットの長さがバラバラであるため、ルータなどの機器が「このパケットはどこまで続くのか」を毎回解析しなければならず、ハードウェアの処理にわずかな時間差（ジッター/揺らぎ）が生まれやすい。

---

### 2. ATM交換方式（Asynchronous Transfer Mode）
かつて、次世代の超高速通信（B-ISDN）の主役として期待された交換方式である。

* **仕組み:** データをパケットではなく、**「セル（Cell）」**と呼ばれる**53バイト（ヘッダー5バイト＋データ48バイト）の完全に固定されたサイズ**に細かく分割して転送する。
* **最大の特徴（固定長）：**
  どんなデータであっても、強制的に53バイトの固定長に切り分けられる。
* **メリット:** サイズが完全に一定であるため、ルータやスイッチなどのハードウェアはパケットの長さを計算する必要がない。機械的に「53バイトごとに処理する」だけで済むため、当時の技術としては**圧倒的に高速かつ、等間隔でのデータ転送（低遅延・QoSの保証）**が可能だった。そのため、途切れることが許されない「音声通話（電話）」や「リアルタイム動画」の統合ネットワークに最適とされた。
* **デメリット:** データのサイズが小さくても無理やり53バイトにするため、無駄な余白（パディング）が多く発生し、回線の効率が悪くなりやすい。また、すべてのデータを細かく刻みすぎるため、ヘッダー（5バイト）の割合が多くなり（約10%がヘッダー）、オーバーヘッドが大きい。

---

### 3. 比較まとめ：なぜ現代はパケット交換が勝ったのか


| 項目 | パケット交換方式（現代の主流） | ATM交換方式（レガシー） |
| :--- | :--- | :--- |
| **データの単位** | パケット（Packet） | セル（Cell） |
| **データの長さ** | **可変長**（サイズが柔軟に変わる） | **固定長**（常に53バイト） |
| **得意な通信** | コンピュータ同士のデータ通信 | 音声や動画などのリアルタイム通信 |
| **現在のステータス** | インターネットの事実上の標準（IP/イーサネット） | インフラの基幹網の一部を除き、ほぼ衰退 |

「ハードウェアが非力だった時代」は、固定長で処理を簡素化できるATMに大きな優位性があった。しかしその後、半導体技術が爆発的に進化し、**「可変長のパケットであっても、ハードウェア（ルータのASICなど）が超高速で処理できる」**ようになった。
その結果、回線効率が良く、システムがシンプルで安価に構築できる「イーサネット＋IP（パケット交換方式）」が世界を席巻し、ATMは技術的な主役の座を譲ることとなった。

## 6. 知識定着チェッククイズ

### Q1. L2スイッチをループ状に配置した際に発生する「ブロードキャストストーム」とはどのような現象か。また、スパニングツリー（STP）はこれをどのように解決するか説明せよ。

**【解答】**
* **現象:** ネットワーク内のすべての端末にデータを届けるための「ブロードキャストフレーム」が、ループ構造によってL2スイッチ間を永遠にぐるぐると転送され続け、増幅していく現象である。これにより帯域とスイッチの処理能力が埋め尽くされ、ネットワーク全体が通信不能（ダウン）になる。
* **解決策:** STPは、スイッチ間で制御情報をやり取りしてネットワークの接続構造を把握し、ループを排除するために**特定のポートを論理的に「ブロッキング状態（通信遮断）」に変える**。これにより、物理的にはループしていても、論理的には一本道の「ツリー構造」に固定することでストームの発生を防ぐ。

---

### Q2. 冗長化の技術において、「スパニングツリー（STP）」と「リンクアグリゲーション（LAG）」のネットワーク資源（帯域幅）の有効活用という観点における違いを述べよ。

**【解答】**
* **STP:** 冗長化のために用意した予備の回線を「論理的に遮断して眠らせておく」ため、障害が発生していない通常時は、予備回線の帯域幅を全く活用できない（宝の持ち腐れになる）。
* **LAG:** 複数の物理回線を「論理的に1本の太い回線に束ねる」ため、通常時からすべての回線にデータを分散して流すことができる。これにより、冗長性を確保しつつ、通信の帯域幅（スピード）を掛け算的に向上させることができるという違いがある。

---

### Q3. 「IPv4」の環境下で、世界中のWebサーバーと社内のPCが通信するために「NAT/NAPT」という技術が実務で広く使われている理由は何か。また、「IPv6」に移行するとこの技術が不要になるのはなぜか答えよ。

**【解答】**
* **使われている理由:** IPv4アドレス（32ビット）は総数が約43億個しかなく、インターネットの普及により世界的に枯渇しているため。社内や家庭内では「プライベートIP」を使い回し、インターネットに出る瞬間だけ少数の「グローバルIP」へNAT/NAPTで変換することで、限られたIPアドレスを節約している。
* **不要になる理由:** IPv6は128ビットのアドレス長を持ち、事実上無限（地球上の砂の数以上）のアドレスを供給できるため。すべての末端デバイスに直接一意なグローバルIPアドレスを割り当てることが可能となり、アドレス枯渇対策としてのIP変換（NAT/NAPT）を行う必要性が根本から消滅するからである。

---

### Q4. 初期の実装である「CSMA/CD」プロトコルが、現代の一般的なオフィスやデータセンターの有線LAN環境（スイッチングハブを用いたフルデュプレックス通信）において不要になったのはなぜか、通信構造の違いを踏まえて説明せよ。

**【解答】**
初期の有線LANは1本の同軸ケーブルを全員で共有していたため、複数の端末が同時に送信するとデータが衝突（コリジョン）していた。
しかし、現代のスイッチングハブを用いた環境では、ハブがMACアドレスを学習して目的地へ個別にデータを届ける。さらに、LANケーブルの内部で「送信専用の線」と「受信専用の線」が物理的または論理的に完全に分かれている**フルデュプレックス（全二重）通信**を行っているため、データが送受信で衝突すること自体が構造上発生しない。したがって、衝突を検知・回避するためのCSMA/CDという仕組み自体が不要になった。
