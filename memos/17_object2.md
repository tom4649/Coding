# カプセル化・抽象化・継承・ポリモーフィズム

## 1. カプセル化（Encapsulation）

**カプセル化**とは、データ（属性）とそれを操作するメソッドを1つのクラスにまとめ、**外部から直接アクセスできないように隠蔽（情報隠蔽）すること**である。

外部には安全な公開窓口（ゲッター/セッター）だけを提供し、不正な値の代入や、内部構造の勝手な変更を防ぐ。

### Pythonでの実装：`@property` と `@...setter`
Pythonには他言語のような `private` キーワードがないため、変数名の前にアンダースコアを2つ `__` つけることでプライベート化し、`@property` デコレータを用いて安全にアクセスさせる。

```python
class BankAccount:

    def __init__(self, owner, balance):
        self.owner = owner
        self.__balance = balance  # アンダースコア2つで外部から隠蔽（プライベート化）

    # ゲッター（外部から値を安全に読み取る用）
    @property
    def balance(self):
        return self.__balance

    # セッター（外部から値を安全に書き換える用・バリデーションが可能）
    @balance.setter
    def balance(self, amount):
        if amount < 0:
            raise ValueError("残高をマイナスにすることはできません。")
        self.__balance = amount


# 使用例
account = BankAccount("Alice", 1000)

print(account.balance)  # 1000 (ゲッターが呼ばれる)
account.balance = 2000  # 2000 (セッターが呼ばれる)
# account.balance = -500  # ❌ ValueErrorが発生し、不正な書き換えを防ぐ
```

外部からは「通常の変数」への代入のように見えるが、裏側ではメソッドによるチェックが走るため、安全性が担保されるのである。

## 2. 抽象化（Abstraction）と抽象クラス・インターフェース

### 抽象化（Abstraction）とは
オブジェクトの複雑な内部実装を隠し、**利用者に必要な「機能の本質（インターフェース）」だけを見せること**である。

### 抽象クラス（Abstract Classes）
不完全なメソッド（中身のないメソッド）を1つ以上持ち、**単体ではインスタンス化できないクラス**である。共通の枠組みを定義し、具体的な処理は子クラスに強制的に実装（オーバーライド）させる。

### 「抽象クラス」と「インターフェース」の違い
Pythonではどちらも `ABC`（Abstract Base Class）で表現するが、設計上の役割は明確に異なる。

| 特徴 | 抽象クラス（Abstract Class） | インターフェース（Interface） |
| :--- | :--- | :--- |
| **本質的な意味** | **「〜の一種である (is-a 関係)」**<br>共通の「血統・土台」を引き継ぐ。 | **「〜の機能・資格を持つ (can-do 関係)」**<br>共通の「ルール・契約」を結ぶ。 |
| **コードの実装** | ⭕ 抽象メソッドだけでなく、**具体的な処理を持つ共通メソッド**も書ける。 | ❌ **原則として処理（中身）は一切書けない。** メソッドのシグネチャのみ。 |

### 抽象化とカプセル化の決定的な違い
この2つは混同されやすいが、視点が「外部」か「内部」かで分かれる。

> **"Abstraction is the external view of an object, while Encapsulation is the internal view."**
> （抽象化はオブジェクトの外部からの視点であり、カプセル化は内部からの視点である）

* **抽象化（外部視点）：** 「何ができるか（What it does）」に注目し、複雑な中身を隠してシンプルなリモコンだけを外に見せる思想。
* **カプセル化（内部視点）：** 「どうやって実現しているか（How it does it）」を保護し、データを鍵付きの箱に隠して安全な窓口からしか触らせない構造。

## 3. 継承（Inheritance）とMRO（Method Resolution Order）

**継承**とは、親クラスの属性やメソッドを子クラスへと引き継ぐ仕組みである。
継承を使うべきかの判断基準は、**「子クラス is a 親クラス（子クラスは親クラスの一種である）」** という関係が成り立つかどうかである。

### メソッド解決順序（MRO）
Pythonのように「多重継承（複数の親クラスを持つこと）」を許す言語では、同名のメソッドがどの親クラスから順番に探索されるかという優先順位のルールが必要になる。これを**MRO**と呼ぶ。

Pythonでは「C3線形化」というアルゴリズムを採用しており、基本的には「深さ優先ではなく、幅優先（子に近い方を優先）」で探索される。

```python
class A:

    def show(self):
        print("Aのメソッド")


class B(A):

    def show(self):
        print("Bのメソッド")


class C(A):

    def show(self):
        print("Cのメソッド")


# BとCを多重継承（左側に書いた方が優先される）
class D(B, C):
    pass


d = D()
d.show()  # 結果: Bのメソッド

# 実際の探索順序（MRO）を確認する
print(D.__mro__)
# 結果: (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
```

探索は `D -> B -> C -> A` の順に行われる。ルートであるAが最後になるのは、枝分かれしたBやCの記述を優先するためである。

## 4. ポリモーフィズム（Polymorphism：多態性）

ポリモーフィズムとは、**「同じ名前のメソッドを呼び出しても、呼び出す対象の型によって、それぞれ異なる独自の振る舞いをする」**仕組みである。これには「コンパイル時」と「実行時」の2種類が存在する。

### ① コンパイル時ポリモーフィズム（Compile-time / 静的）
同じクラス内で、名前は同じだが引数の数や型が異なるメソッドを複数定義する**メソッドオーバーロード（Method Overloading）**がこれに該当する。
※Pythonは動的型付け言語であるため、仕様としてネイティブなオーバーロードは存在せず、主にJavaなどの静的型付け言語の概念である。

### ② 実行時ポリモーフィズム（Runtime / 動的）
親クラスで定義されたメソッドを、子クラス側で全く別の処理として再定義する**メソッドオーバーライド（Method Overriding）**によって実現される。LLDの本質であり、システムの結合度を下げるために極めて重要である。

```python
class Shape:

    def draw(self):
        pass


class Circle(Shape):

    def draw(self):
        return "◯を描く"


class Square(Shape):

    def draw(self):
        return "□を描く"


# 呼び出し側の関数：相手がCircleかSquareか知らなくても、Shapeであれば動く
def render_shape(shape: Shape):
    print(shape.draw())  # 実行時にオブジェクトの型を見て、適切なdrawが選ばれる


render_shape(Circle())  # ◯を描く
render_shape(Square())  # □を描く
```

### Q1. 「Abstraction（抽象化）」と「Encapsulation（カプセル化）」の違いを、「外部視点」「内部視点」という言葉を使って説明せよ。

<details>
<summary>正解と解説を見る</summary>

**正解：**
抽象化はオブジェクトの**外部視点（External View）**であり、複雑な実装を隠して「何ができるか」というシンプルなインターフェースのみを提示する思想である。一方、カプセル化はオブジェクトの**内部視点（Internal View）**であり、「どうやって実現しているか」というデータと処理を隠蔽し、不正な操作から保護する構造である。

</details>

### Q2. Pythonの多重継承において、メソッドの探索順序（MRO）はどのようなルールに従って決定されるか？

<details>
<summary>正解と解説を見る</summary>

**正解：**
Pythonでは「C3線形化」アルゴリズムが採用されており、基本的には「深さ優先」ではなく**「幅優先（共通の親クラスに到達する前に、並列する子クラスを先に探索する）」**の順序になる。また、クラス定義の際に左側に記述された親クラスが優先される。

</details>

---

### Q3. 「実行時ポリモーフィズム（Runtime Polymorphism）」を実現するために、オブジェクト指向で用いられる代表的な仕組みは何か？

<details>
<summary>正解と解説を見る</summary>

**正解：**
**メソッドオーバーライド（Method Overriding）**である。親クラスやインターフェースが持つメソッドを子クラスで上書き定義することにより、実行時に渡されたオブジェクトの型に応じて動的に振る舞いを切り替えることができる。

</details>
