# 分散コンピューティングの基本概念

## 1. サービス指向アーキテクチャ（SOA）と マイクロサービス

分散システムを構築する第一歩は、巨大で密結合なアプリケーション（モノリス）を、機能ごとの小さな単位に分解することである。

* **仕組み:** システムの機能（例：認証、商品検索、注文処理、配送管理など）を独立した「サービス」として分割し、それぞれがネットワーク（APIやRPC、メッセージキュー）を介して通信・連携する設計思想である。
* **SOAとマイクロサービスの違い:** * **SOA（Service-Oriented Architecture）:** 企業全体のシステム統合を主眼に置き、比較的大きめの単位でサービスを分割する。サービス間の連携にはESB（エンタープライズ・サービス・バス）と呼ばれる中央集権的な仕組みが使われることが多い。
    * **マイクロサービス（Microservices）:** SOAを進化させたモダンな形態であり、さらに小さく、完全に独立した単位でサービスを分割する。各サービスが独自のデータベースを持ち、DevOpsやコンテナ技術と密接に結びついている。
* **分散におけるメリット:**
    * **独立したスケーリング:** 「決済サービス」だけが高負荷であれば、決済のサーバーだけをピンポイントで水平スケーリングできるため、コスト効率が極めて高い。
    * **障害の隔離:** 万が一「おすすめ商品提案サービス」がダウンしても、システム全体を巻き込まず、コア機能である「注文処理」は維持できる（疎結合）。

## 2. マップリデュース（MapReduce）と ビッグデータ処理

数テラバイト、数ペタバイトに及ぶ膨大なログデータや購買履歴を、1台のコンピュータで集計・分析することは不可能である。これを複数台のサーバーで並列処理するためのフレームワークが**MapReduce**である。

処理は大きく2つのステップに分解される。

* **Map（マップ）フェーズ:**
    * 膨大な元データを小さく分割し、クラスター内の複数のサーバー（ワーカー）へ同時に分配する。
    * 各サーバーは、割り当てられたデータから必要な情報（キーワードなど）を抽出し、「キー（Key）と値（Value）」のペアを生成する。
* **Reduce（リデュース）フェーズ:**
    * Mapフェーズで生成されたデータの中から、**同じキーを持つものを1つのサーバーに集約（シャッフル）**する。
    * 集約されたデータを合算・集計し、最終的な1つの出力結果を取り出す。

> MapReduceの真髄は、**「データをプログラムのある場所に移動させるのではなく、データが存在する場所にプログラム（計算処理）を送り込んで並列処理させる」**点にある。これにより、ネットワーク通信のボトルネックを最小限に抑え、ビッグデータの高速集計を可能にしている。

## 3. 分散キャッシュ（Distributed Caching）

単一のメモリ（キャッシュサーバー）の容量上限を超えた、あるいは地理的に分散したユーザーに対して超高速な応答を返すための仕組みが**分散キャッシュ**である。代表的なプロダクトとして Redis Cluster や Memcached が挙げられる。

* **仕組み:** キャッシュデータを1台のサーバーではなく、複数のキャッシュノードに分散して保持する。
* **データの分散アルゴリズム（Consistent Hashing）:**
    * データを単に `ノード数で割った余り（ハッシュ値 % ノード数）` で分散させると、サーバーが1台増減しただけで、全てのキャッシュの保存先が変わってしまい、大量のキャッシュミス（システム全体の過負荷）を招く。
    * これを防ぐため、分散キャッシュでは**一貫性ハッシュ法（Consistent Hashing）**が採用される。これにより、サーバーの追加・削除が発生した際も、移動が必要なデータ（キャッシュの再配置）を最小限に抑えることができる。

## 4. 負荷分散（Load Balancing）の高度な役割

分散システムにおいて、ロードバランサーは単にトラフィックを均等に分けるだけでなく、インフラ全体の「トラフィックの交通整理」を担う。

* **DNSラウンドロビンによる大枠の分散:**
    * ユーザーがドメイン（例：`amazon.com`）にアクセスした際、DNSサーバーが世界各地のデータセンターのIPアドレスを順番（または位置情報ベース）に返すことで、国・地域レベルでの地理的な負荷分散（GSLB）を行う。
* **レイヤー4（L4）およびレイヤー7（L7）ロードバランサー:**
    * データセンターの内部に到達したトラフィックは、ハードウェアまたはソフトウェアのロードバランサーによって処理される。
    * **L4（トランスポート層）:** IPアドレスとポート番号だけを見て、高速にパケットをサーバー群へ振り分ける。
    * **L7（アプリケーション層）:** HTTPリクエストのヘッダー、URLのパス（例：`/cart` と `/search` で転送先を分ける）、Cookieの内容を解析し、適切なマイクロサービスへとインテリジェントにルーティングを行う。

## 5. 知識定着クイズ

* **Q1.** モノリシックなシステムを「マイクロサービス（あるいはSOA）」に分割する際、システム全体の拡張性（スケーラビリティ）は向上するが、引き換えに発生する「ネットワーク通信」や「データの一貫性」におけるトレードオフ（デメリット）について説明せよ。

**【解答例】**
* **ネットワーク通信のトレードオフ:**
  単一のメモリ内で完結していた関数呼び出しが、サービス間のネットワーク通信（REST APIやRPC）に置き換わるため、ネットワークの遅延（レイテンシ）が増大し、通信障害によるエラーハンドリングの複雑さが増す。
* **データの一貫性のトレードオフ:**
  各サービスが独立したデータベースを持つため、複数のサービスにまたがる処理でRDBのような厳格な「ACID特性（リアルタイムな一貫性）」を保つことが極めて困難になる。そのため、システム全体としては「最終的にデータの矛盾が解消されれば良い」という**結果整合性**（2相コミットやSagaパターンなどの高度な設計）を受け入れる必要がある。
</details>

* **Q2.** マップリデュース（MapReduce）アーキテクチャにおいて、「Map」と「Reduce」の間で発生するデータの並び替え・移動処理を何と呼ぶか。また、この処理が大量データ転送においてボトルネックになりやすい理由を述べよ。

### Q2 の解答・解説
<details>
<summary>解答・解説を見る</summary>

**【解答例】**
「Map」と「Reduce」の間で発生するデータの並び替え・移動処理は、**シャッフル（Shuffle / Shuffle and Sort）**と呼ばれる。
シャッフル処理では、Mapフェーズに出力された膨大な中間データ（Key-Valueペア）を、Keyごとに集約するためにネットワークを介して別のサーバーへ一斉に転送（全対全の通信）する必要がある。この時、膨大なネットワーク帯域を消費するため、ネットワークの転送速度がシステム全体の処理速度を決める最大のボトルネック（I/Oボトルネック）になりやすい。
</details>

* **Q3.** 分散キャッシュシステムにおいて、キャッシュノード（サーバー）の台数が動的に増減する環境下で、単純な剰余（%）によるハッシュ割り当てではなく「一貫性ハッシュ法（Consistent Hashing）」を採用すべき理由を、キャッシュミスの観点から説明せよ。

### Q3 の解答・解説
<details>
<summary>解答・解説を見る</summary>

**【解答例】**
単純な剰余（%）による割り当て（`ハッシュ値 % ノード数`）では、サーバーの台数が1台でも増減すると、分母が変わるため**ほぼ全てのデータの格納先（割り当て先ノード）がガラリと変わってしまう**。その結果、既存のキャッシュのほとんどがヒットしなくなる「大規模なキャッシュミス（キャッシュスラッシング）」が発生し、バックエンドのデータベースにアクセスが集中してシステムがダウンするリスクがある。
一方、**一貫性ハッシュ法（Consistent Hashing）**を採用すれば、サーバーの増減が発生した際も、影響を受ける（再配置が必要になる）データが全体の「`1 / 変更後のサーバー台数`」程度に抑えられるため、キャッシュミスを最小限に留め、システムを安定させることができる。
</details>

* **Q4.** レイヤー4（L4）ロードバランサーとレイヤー7（L7）ロードバランサーの違いを説明し、「URLのパス（例: `/api/v1/users`）に応じて、転送先のアプリケーションサーバーを切り替えたい」という要件を満たすにはどちらを採用すべきか答えよ。

### Q4 の解答・解説
<details>
<summary>解答・解説を見る</summary>

**【解答例】**
* **L4（トランスポート層）ロードバランサー:**
  IPアドレスとポート番号（TCP/UDP）という低レイヤーの情報だけを見て機械的にトラフィックを振り分ける。パケットの中身（HTTPの中身）を解析しないため、処理が極めて高速である。
* **L7（アプリケーション層）ロードバランサー:**
  HTTP/HTTPSリクエストの中身（URL、ヘッダー、Cookie、データ内容など）まで深く解析してインテリジェントにルーティングを行う。L4に比べると解析のためのCPU負荷は高くなる。

**【要件への回答】**
「URLのパス（例: `/api/v1/users`）に応じて転送先を切り替えたい」という要件を満たすには、HTTPリクエストのURL文字列を解析する必要があるため、**レイヤー7（L7）ロードバランサー**を採用すべきである。
</details>
